工業 AI 視覺工程師｜自動控制背景　·　台中

三個產業的產線瑕疵檢測落地，一套訓練後端支撐 4 個客戶約 50 個版本。三個手工特徵消掉約 70% 誤報。3D 定位現場誤差 1 cm。3.5 週從零到展會 demo。

2023.08 – 2026.06　自動化系統整合商工程師　·　自動控制本科

關於

自動控制本科，在自動化系統整合商擔任工程師三年（2023.08–2026.06）。做的是把 AI 檢測裝進既有產線的完整流程：相機與光源選型、影像擷取策略、特徵分析與模型選型、推論加速、服務化常駐與現場維運。設備端自己接 —— 相機觸發、光源、PLC 交握。

選型靠數據不靠直覺：六種異常偵測模型做完整 benchmark 再決定；3D 案評估後放棄 PointNet，幾何特徵 + DBSCAN 就夠。最後一年自己定調 GUI 架構、Ed25519 授權機制與部署工具鏈，並主導商用模型授權合規調查。

症狀像硬體，根因在 library。

曾追一個只在現場那台機器上發生的 crash。抓 dump 比對，三份 failure hash 完全相同 —— 硬體不會每次死在同一個位址。翻 OpenVINO 原始碼找到文件沒寫的預設值開了 64 條閒置執行緒在跟 asyncio 搶 GIL。

所以系統要穩，硬體、驅動、軟體版本、library 參數、組合測試，每一層都得親手顧過 —— 模型只是其中一層。

工業表面瑕疵檢測系統

2024.09 – 2026.03　·　主要開發負責

三個產線案表面上獨立，但中間那段不該重複做。所以真正解的是兩層問題：每個現場條件都不同，而模型訓練與版本管理應該只做一次。

  • 複合材料連續產線　24/7 連續運行，版本 1000.0.3 → 1000.0.25 凍結版；NSSM 服務化讓 crash 自動重啟；通過委託單位正式稽核
  • 粒子分析邏輯　小面積 × 高圓形度 × 低熵暗點，搭配覆蓋機制消除約 70% 外膜髒污誤報
  • 食品加工產線　ReverseDistillation + ResNet34，驗證 AUROC 1.0 / F1 1.0，OpenVINO 匯出 69.4 MB；現場推論 4 張 512×512 約 0.25 秒
  • 工具機產業展會　3.5 週從零到功能全數完成，含相機架設、光源、取像、訓練、驗證；依 CPU-only 條件選 STFPM，模型僅 21.35 MB
  • 共用訓練後端　六類端點、anomalib 六模型 benchmark、branch + tag 管理 4 客戶約 50 個 tag；推論非同步化解決 FastAPI 阻塞

Python · PyTorch · anomalib · OpenCV · FastAPI · OpenVINO · Intel Arc GPU · NSSM

3D 點雲定位與機械手臂取放

2024.06 – 2026.03　·　主要單人開發

唯一一條完全獨立於共用後端的技術線，也是最接近「單人從零做完」的專案。

  • 投射紋理立體相機　純被動雙目在無紋理表面找不到對應點；主動投射隨機點等於替表面加上紋理，在金屬與素色工業件上才穩得住
  • 放棄深度學習　原計畫 PointNet / DGCNN，評估後改用 DBSCAN + 幾何特徵。物件固定、背景可控，深度模型的泛化能力沒有使用場景，卻要付完整的標註與維護成本
  • 參數化設計　六大參數群（transform / grip / read_ply / roi_box / voxel_down_sample / dbscan），現場調整不需改程式碼
  • 現場高度與半徑誤差 1 cm　捲尺實測比對；cx_Freeze 打包，並產出座標系校正說明讓現場自行重校

Python · Open3D · DBSCAN · 點雲 ROI / voxel down sample · 立體相機 SDK · cx_Freeze

VisionFlow — SOP 工序電子化與即時監控

2026.01 – 2026.04　·　系統負責人

第一次從架構、授權到部署工具鏈全部自己定調。「要能賣」這三個字改變了每一個技術決策。

  • PySide 6　目標是產線旁的工控機，要離線、要存取本機硬體、要長時間常駐。網頁方案多一層相依，換不到對應好處
  • Ed25519 + 機器指紋　對稱加密的金鑰必須放客戶端，等於把鎖跟鑰匙一起交出去。非對稱簽章讓私鑰不離開簽發端
  • YOLOv11s-seg + TensorRT　必須明確指定 cu12 —— 預設的 cu13 與環境 CUDA 12.8 不相容，而錯誤訊息不會告訴你版本對不上
  • 需求收斂　客戶 review 11 項 + 追加 7 項全數收斂。做法是重大 review 一律走視訊、議題一律文件彙整，讓每項變更都有紀錄
  • 商用模型授權調查　code 與 weights 兩層分查，排除 AGPL / GPL 方案，選定 Apache 2.0 / MIT；評估 Thomson Reuters v. Ross（2025）判例影響，建立 training data provenance sheet 制度

Python · PySide 6 · YOLOv11-seg · TensorRT · Ed25519 · Poetry plugin

CV 多任務標註暨訓練平台

2024.06 – 2026.04　·　主要單人開發

標註工具原本是桌面版，多人協作與流程規範化困難。網頁化時不只搬介面，而是把標註 → 格式轉換 → 資料擴增 → 訓練整條線接起來。

  • SAM2 多幀半自動標註　第一幀點選、後續幀傳播，人只需修正。對連續取像的資料集是量級差別
  • 格式轉換防錯　ISAT ↔ YOLO-seg 的 group / layer 層級處理不好會靜默丟失標註，要到訓練結果不對勁才發現。無法對應的結構直接報錯，不做「盡力而為」的猜測
  • 擴增與標註同步　輸出存於時間戳資料夾並保存該次參數設定檔，任何一批訓練資料都能回溯怎麼產生的
  • 4 個訓練後端整合、3 種訓練類型　交接時已產出 4 份使用者文件與 4 份 backend README

Vite · Python · FastAPI · SAM2 · ISAT · YOLO-seg · MLflow
