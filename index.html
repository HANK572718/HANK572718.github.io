關於

自動控制本科，在自動化系統整合商擔任工程師（2024.03–2026.06）。做的是把 AI 檢測裝進既有產線的完整流程：相機與光源選型、影像擷取策略、特徵分析與模型選型、推論加速、服務化常駐與現場維運。設備端自己接 —— 相機觸發、光源、PLC 交握。

  • 先比較、再選擇。模型不憑印象挑：同一批現場資料跑過六種異常偵測模型，看數字決定；3D 案先試了深度學習，發現傳統幾何方法就夠準，就用簡單的那個。瑕疵檢測 →3D 定位 →
  • 重複的事做成工具。三條產線的檢測案共用一套訓練後端，標註、訓練到部署接成一條線 —— 新案子不必從零開始，每一版模型也查得到是用哪批資料訓練的。瑕疵檢測 →標註平台 →
  • 從寫功能到負責整個產品。最後一年主導 VisionFlow：架構、授權保護、部署流程、商用模型的授權合規都自己定，第一次為「能不能賣」負責。VisionFlow →

症狀像硬體，根因在 library。

曾追一個只在現場那台機器上發生的 crash。抓 dump 比對，三份 failure hash 完全相同 —— 硬體不會每次死在同一個位址。翻 OpenVINO 原始碼找到文件沒寫的預設值開了 64 條閒置執行緒在跟 asyncio 搶 GIL。

所以系統要穩，硬體、驅動、軟體版本、library 參數、組合測試，每一層都得親手顧過 —— 模型只是其中一層。

工業表面瑕疵檢測系統

2024.09 – 2026.03　·　主要開發負責

三個產線案表面上獨立，但中間那段不該重複做。所以真正解的是兩層問題：每個現場條件都不同，而模型訓練與版本管理應該只做一次。

  • 複合材料連續產線　隨產線班次每日運行，約 9 個月、二十餘個版本迭代後凍結；NSSM 服務化：開機即啟動、crash 自動重啟；通過委託單位正式稽核
  • 粒子分析邏輯　小面積 × 高圓形度 × 低熵暗點，搭配覆蓋機制消除約 70% 外膜髒污誤報
  • 食品加工產線　ReverseDistillation + ResNet34，驗證 AUROC 1.0 / F1 1.0，OpenVINO 匯出 69.4 MB；現場推論 4 張 512×512 約 0.25 秒
  • 工具機產業展會　3.5 週從零到功能全數完成，含相機架設、光源、取像、訓練、驗證；依 CPU-only 條件選 STFPM，模型僅 21.35 MB
  • 共用訓練後端　六類端點、anomalib 六模型 benchmark、branch + tag 管理 4 客戶約 50 個 tag；推論非同步化解決 FastAPI 阻塞

3D 點雲定位與機械手臂取放

2024.06 – 2026.03　·　視覺端獨立開發，手臂控制由其他團員實作

以 Ensenso 工業 3D 相機定位廢棄馬達，從點雲算出夾取點交給機械手臂；視覺端從取像到輸出夾取點獨立完成。

  • 調手臂、校手眼，即時可視化　自製 3D Viewer 把點雲、分群結果與夾取點畫在同一個畫面，游標停在物件上同時顯示手臂座標與相機座標；調整手臂參數或重校手眼座標時結果當場反映，不用等手臂真的動了才知道對不對
  • 放棄深度學習　原計畫 PointNet / DGCNN，評估後改用 DBSCAN + 幾何特徵。物件固定、背景可控，深度模型的泛化能力沒有使用場景，卻要付完整的標註與維護成本
  • 參數化設計　六大參數群（transform / grip / read_ply / roi_box / voxel_down_sample / dbscan），現場調整不需改程式碼
  • 現場高度與半徑誤差小於 1 cm　捲尺實測比對；手眼座標轉換（相機系 → 手臂系）演算法自行實作，並產出座標系校正說明讓現場自行重校

VisionFlow — SOP 工序電子化與即時監控

2026.01 – 2026.04　·　系統負責人

第一次從架構、授權到部署工具鏈全部自己定調。「要能賣」這三個字改變了每一個技術決策。

  • 技術選型跟著情境走　跑在產線旁的工控機上，要離線、要長時間常駐、要直接接相機與硬體，所以做成桌面應用而不是網頁；產品要賣，授權檔就綁機器指紋、用非對稱簽章驗證，簽發用的私鑰不離開公司；影像端是物件偵測／實例分割任務，經 TensorRT 加速後常駐推論
  • 需求收斂　客戶 review 11 項 + 追加 7 項全數收斂。做法是重大 review 一律走視訊、議題一律文件彙整，讓每項變更都有紀錄
  • 商用模型授權調查　code 與 weights 兩層分查，排除 AGPL / GPL 方案，選定 Apache 2.0 / MIT；評估 Thomson Reuters v. Ross（2025）判例影響，建立 training data provenance sheet 制度

CV 多任務標註暨訓練平台

2024.06 – 2026.04　·　主要單人開發

標註工具原本是桌面版，多人協作與流程規範化困難。網頁化時不只搬介面，而是做成一站式平台：標註 → 格式轉換 → 資料擴增 → 訓練 → 驗證整條線接起來，並以 Docker Compose 交付。

  • 三種任務、一個平台　物件偵測、實例分割、瑕疵檢測（異常偵測）共用同一條標註 → 轉換 → 擴增 → 訓練 → 驗證的流程。訓練前先驗證資料集，訓練後 mAP／PR 曲線與混淆矩陣直接在平台上看
  • 跟模型一起標　SAM2 點一下、框一下就出輪廓，多幀傳播讓連續取像的資料只需修正不用重畫；推論頁可對整個資料夾批次推論，結果直接標為正常／異常，人只做確認
  • Docker Compose 服務化架構　前端（nginx）、API（FastAPI + MLflow）與 YOLO／RF-DETR／Anomalib 三個訓練後端各自獨立容器，跑在同一個 bridge 網路；每個後端可各自指定 GPU，資料、模型與歷史全在掛載的主機目錄，容器隨時可重建。開發環境用 override 疊在同一份 compose 上：熱重載，且與正式環境並存
  • 交付即安裝　離線映像包 + install.sh 一鍵部署；模型服務用 compose profile 開關，客戶自選要啟用哪幾個，關掉的後端 API 優雅降級而不是掛掉。交接附 4 份使用者文件與 4 份 backend README
